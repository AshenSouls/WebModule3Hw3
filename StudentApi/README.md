### Получить всех студентов

```bash
curl -i http://localhost:5133/api/students
```

Ожидаемый результат: `HTTP/1.1 200 OK` и массив из трех студентов. В журнале появится сообщение уровня `Information`.

### Получить существующего студента

```bash
curl -i http://localhost:5133/api/students/1
```

Ожидаемый результат: `HTTP/1.1 200 OK` и данные студента с идентификатором `1`.

### Запросить несуществующего студента

```bash
curl -i http://localhost:5133/api/students/999
```

Ожидаемый результат: `HTTP/1.1 404 Not Found`. В журнале появится сообщение уровня `Warning`.

### Коды ответов

`200 OK` означает, что GET-запрос выполнен успешно. `404 Not Found` означает, что студент не найден. Код `201 Created` используется после создания нового ресурса

## 2. Контрольные вопросы

### 1. Что такое Dependency Injection?

Dependency Injection, или внедрение зависимостей, означает, что объект получает готовые зависимости извне, а не создаёт их сам через `new`. Так код проще тестировать и изменять.

### 2. Зачем использовать интерфейс вместо прямого создания объекта через `new`?

Интерфейс задаёт общий контракт. Контроллеру не важно, какой именно класс выполняет работу, поэтому реализацию можно заменить или подменить тестовой.

### 3. Что такое Constructor Injection?

Это передача зависимостей через конструктор класса. В нашем случае ASP.NET Core сам передаёт в `StudentsController` `IStudentService` и `ILogger<StudentsController>`.

### 4. Для чего сервис регистрируется в `Program.cs`?

Регистрация сообщает DI-контейнеру, какой класс нужно создать, когда приложение попросит `IStudentService`, и сколько должен жить его экземпляр.

### 5. Для чего используется `ILogger<T>`?

`ILogger<T>` записывает диагностические сообщения приложения. По ним можно понять, что произошло во время обработки запроса.

### 6. Чем отличаются `LogInformation`, `LogWarning` и `LogError`?

`LogInformation` описывает обычное событие, `LogWarning` предупреждает о потенциально нежелательной ситуации, а `LogError` сообщает об ошибке и может сохранить её исключение.

### 7. Чем отличаются `Transient` и `Singleton`?

`Transient` создаёт новый экземпляр сервиса при каждом запросе зависимости. `Singleton` создаёт один экземпляр на всё время работы приложения. Singleton экономит создание объектов, но его общее состояние должно быть потокобезопасным и не должно случайно сохраняться между запросами. В этом проекте используется `AddTransient<IStudentService, StudentService>()`.
